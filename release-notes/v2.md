**<변경점>**

**1. 터미널이 아닌 맵을 끝낸 뒤 메뉴에서 메모리가 남던 것**
- 터미널 모드를 깔아 두고 다른 맵(리저브·세관 등)을 끝내면, 메뉴에서도 그 맵의 날씨 관리자가 메모리에 남아 다음 레이드 시작 때까지 풀리지 않았습니다. 날씨 관리자에 그 맵의 장면 데이터가 줄줄이 매달려 있어서 RAM 클리너 누수 보고에 터미널 모드가 붙잡은 것으로 나왔습니다.
- 터미널 모드는 날씨 연결을 위해 모든 맵의 날씨 관리자를 기억해 두는데, 레이드가 끝났을 때 그 기억을 지우는 정리는 터미널 레이드에서만 돌았습니다.
- 이제 다른 맵 레이드가 끝날 때도 그 기억을 지웁니다. 터미널 레이드의 원래 정리 순서는 그대로입니다.
- 확인: 게임 시뮬(리저브 20분 2판, 연구소 20분 1판) — 레이드가 끝난 뒤 RAM 클리너 누수 목록에 터미널 모드 없음. Codex 코드 검토 — 문제 없음, 같은 종류의 다른 누수 없음(파일 193개 대조).

**2. 기타**
- 배포 압축에 ORBIT MIT 라이선스 원문(`BepInEx/plugins/ManimalTerminal/licenses/ORBIT-LICENSE.txt`)을 넣고, README 고지문에 ORBIT 저작권을 표기했습니다(v1 게시 직후 압축에 넣은 것과 같음).

**알려진 점**
- 이번 수정은 터미널이 아닌 맵에서 돌린 게임 시뮬로 확인했습니다. 터미널 맵 자체의 동작(유령 모드 등)은 v1과 같은 코드라 다시 돌려 보지 않았습니다.

**<Changes (English)>**

**Previous release:** v1 (`zzap-v1`, published 10/28, 5 commits since - one code change, the rest notes, README and license credit) → **this: v2**, a bug fix. Release file: `Manimal-Terminal-0.2.20-zzap-v2.zip`, same layout as v1; only the client `ManimalTerminalClient.dll` changed.

**1. Memory kept in the menu after a non-Terminal raid**
- With Terminal installed, ending another map (Reserve, Customs, ...) left that map's weather controller alive in the menu until the next raid, with the map's scene data hanging off it; the RAM cleaner leak report listed the Terminal mod as the holder.
- The Terminal mod records every map's weather controller for its weather hookup, but the cleanup that forgets it ran only for Terminal raids.
- It is now forgotten when any other raid ends too. The Terminal raid cleanup order is unchanged.
- Checked: in-game sim (Reserve 20 min × 2, Labs 20 min × 1) - the Terminal mod is gone from the RAM cleaner leak list after the raid. Codex review: no issues, no other leak of the same kind (193 files).

**2. Other**
- The release zip carries the ORBIT MIT license text (`BepInEx/plugins/ManimalTerminal/licenses/ORBIT-LICENSE.txt`) and the README notice credits ORBIT's copyright (same as added to the v1 zip right after it was published).

**Known issues**
- The fix was checked in non-Terminal raids; the Terminal map itself (Ghost Mode etc.) runs the same code as v1 and was not re-run.
- v1's known issues stay (a brief hitch when a bot first appears, a `BaseLocalGame.CleanUp` error logged at raid end).

**Install / update**
- **Install the original Manimal Terminal 0.2.20 first** (this zip has no map bundles): https://pub-38fba86cac60421ebd03a218d2535c13.r2.dev/Manimal-Terminal-SPT-4.1-0.2.20.zip
- Extract `Manimal-Terminal-0.2.20-zzap-v2.zip` into your SPT folder and overwrite. Settings are kept. From v1 only the client DLL changes.

**!!!!!!!!!!!PLEASE READ THIS!!!!!!!!!!!**

Hi everyone,

I'd like to share a few thoughts and important warnings regarding the process of porting mods from version 4.0 to 4.1.

Following the recent "ECOT" mod incident, I've had a lot of time to reflect on my actions.
I’m not here to lecture anyone—I’m writing this simply in the hope that you’ll keep these points in mind.


**1. I am not a professional programmer; I am mostly a "vibe coder" who relies heavily on AI.**

By that, I mean I’m not someone who spends days designing and painstakingly crafting mods by hand from scratch.
At the same time, having tinkered with simple mod edits back in the TS/JS (SPT 2.3.1) days, I know firsthand how much time, effort, and care goes into this process.
Therefore, even if a mod is covered under an MIT License, if the original author requests that I delete the source code and stop distribution, I will willingly comply.


**2. Please DO NOT re-distribute or re-upload these modified mods to 3rd/4th party places.**

Even if my ported version has some fixes or improvements, please do not treat it as a long-term solution. Unlike official releases on "THE FORGE," I do not perform thorough debugging or full security scans.
Furthermore, imagine how disruptive it would be if someone mistook my ported build for an "official release" and pestered the original author about bugs in my version. It would be terrible.
Moving forward, I intend to approach any porting work with the utmost respect for original modders.
If I had spent days pouring my heart into making a mod, only to have someone take my code and modify it however they pleased, I wouldn't feel good about it either.
Therefore, when writing README.md files on GitHub, I will always credit the original creators, and if it's not a mod I built from scratch, I will fully respect the original modder's decisions and opinions.


**3. Please respect the original creators.**

If people ignore warning 2. and act as if my port is the "real deal," I would feel immense guilt.
Please do not do that. As the saying goes, "When in Rome, do as the Romans do"—and showing proper respect and courtesy is essential.
Instead, please visit the original creators' comment sections on The Forge to leave warm words of appreciation, encouragement, or even buy them a coffee/leave a tip if you can


**Thank you for reading this long post.**
**Stay safe and stay happy!**
